# Auth (static tokens + OIDC) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bearer-token auth on the pglord API: operator-configured static tokens and/or OIDC resource-server JWT validation, with UI login (token paste + PKCE), opt-in with open-by-default back-compat.

**Architecture:** One axum middleware on the API router checks `Authorization: Bearer` — static token (constant-time) first, then OIDC JWT against a lazily-fetched cached JWKS. A public `GET /api/v1/auth/config` tells the UI which login affordances to render. The Angular UI adds an auth service + functional interceptor + route guard + `/login` page with a hand-rolled PKCE service. Spec: `docs/superpowers/specs/2026-08-02-auth-design.md`.

**Tech Stack:** Rust (axum 0.8, `jsonwebtoken`, `subtle`, existing reqwest/figment/utoipa), Angular 22 (signals, functional interceptors, Transloco), Helm + raw manifests.

## Global Constraints

- Never hand-edit `spec/openapi.yaml` or `ui/src/app/api/**` — run `make openapi ui-client` after API changes and commit regenerated files with the code.
- Clippy warns on `unwrap_used`; Rust edition 2024. `make lint` must pass (fmt + clippy -D warnings).
- All user-visible UI strings go through Transloco (`ui/public/i18n/en.json`).
- Error responses use `error.rs` `ApiError` (problem+json, stable `code` field). New codes: `auth_required`, `auth_invalid`.
- API paths are versioned: `/api/v1/...`. The anonymous auth-config path is `/api/v1/auth/config`.
- `deploy/k8s/` and `charts/pglord/` must stay in sync (same env wiring shown in both).
- Auth unconfigured → behavior identical to today (open), plus one startup `warn!`.
- `Config::test_default()` must gain the new fields so existing tests keep compiling.

**Interfaces:**
- Produces: `pub struct OidcValidator { issuer: String, audience: String, client_id: String, http: reqwest::Client, cache: tokio::sync::Mutex<KeyCache> }`, `OidcValidator::new(issuer, client_id, audience, http)`, `pub async fn validate(&self, token: &str) -> bool`, plus `pub fn issuer(&self) -> &str`, `pub fn client_id(&self) -> &str` for the config endpoint.

### Task 6: UI — auth service, interceptor, guard, login page, PKCE

**Files:**
- Create: `ui/src/app/core/auth/auth.service.ts`, `ui/src/app/core/auth/auth.interceptor.ts`, `ui/src/app/core/auth/auth.guard.ts`, `ui/src/app/core/auth/oidc.service.ts`, `ui/src/app/pages/login/login.component.ts`, `ui/src/app/pages/login/callback.component.ts`, `ui/src/app/core/auth/auth.service.spec.ts`, `ui/src/app/core/auth/auth.interceptor.spec.ts`
- Modify: `ui/src/app/app.config.ts` (`provideHttpClient(withInterceptors([authInterceptor]))`), `ui/src/app/app.routes.ts` (`/login`, `/login/callback` outside shell; `canActivate: [authGuard]` on the shell route), `ui/src/app/shell/shell.component.ts` (logout button when a credential exists), `ui/public/i18n/en.json` (`auth.*` strings)

**Interfaces:**
- `AuthService`: `token: Signal<string | null>`; `setStatic(token: string)`, `setOidc(tokens: {accessToken, refreshToken?, expiresAt?})`, `logout()`; persists `{kind, accessToken, refreshToken?, expiresAt?}` in `localStorage['pglord.auth']`; `authConfig()` fetches `/api/v1/auth/config` once via the generated service and caches the promise; `enabled()` derived from it.
- `authInterceptor` (functional `HttpInterceptorFn`): if a token exists and the request URL targets the API root, set `Authorization: Bearer <token>`; on 401 error from a non-auth-config call: `AuthService.logout()` + `Router.navigate(['/login'])`, rethrow.
- `authGuard` (`CanActivateFn`): `await authConfig()`; auth disabled → true; token present → true; else `router.createUrlTree(['/login'])`.
- `OidcService`: `beginLogin(issuer, clientId)` — fetch `<issuer>/.well-known/openid-configuration`, generate PKCE verifier (43 random chars) + S256 challenge (WebCrypto), `state` + `nonce` to `sessionStorage['pglord.oidc']`, redirect to `authorization_endpoint` with `response_type=code&scope=openid profile&redirect_uri=<origin>/login/callback`; `completeLogin()` — on the callback route: verify `state`, POST `token_endpoint` (`grant_type=authorization_code`, `code_verifier`), store via `AuthService.setOidc`, navigate `/`; `scheduleRefresh()` — if `refreshToken` and `expiresAt`, timer at `expiresAt - 60s` posting `grant_type=refresh_token`; on failure logout.
- Login page: reads `authConfig()`; renders token-paste form (static enabled) and/or "Sign in with {{host}}" button (OIDC enabled); token submit → `setStatic` + probe `GET /api/v1/version` → success navigate `/`, 401 → inline error `auth.badToken`.
