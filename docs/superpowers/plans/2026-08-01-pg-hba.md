# pg_hba.conf Editing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Editable client access rules (`pg_hba.conf`) via the cluster spec: structured rules validated in core, rendered as the whole file by the agent, applied with a reload.

**Architecture:** New `pglord_core::hba` module (types, validation, whole-file render) plugged into `ClusterSpec`/`SpecChange`; the agent writes the rendered file at bootstrap and converges it in the existing spec-watch loop; the server only maps the new error and exposes the field; UI adds a rules dialog. Spec: `docs/superpowers/specs/2026-08-01-pg-hba-design.md`.

**Tech Stack:** Rust (axum/utoipa/serde/thiserror), Angular + spartan-ng hlm + Transloco, bash e2e on the minikube stand.

## Global Constraints

- Managed prefix is fixed: `local all all peer`, loopback scram, `local replication all peer`, `host replication <repl_user> 0.0.0.0/0 scram-sha-256`; managed catch-all `host all all 0.0.0.0/0 scram-sha-256` is always last. Trust variants when no password is configured (see spec).
- Auth method allowlist: `scram-sha-256`, `reject`, `trust`. Serde-level: unknown methods are unrepresentable.
- User rules: connection types `host|hostssl|hostnossl` only (no `local`); database is `all`, `replication`, or an identifier `[A-Za-z_][A-Za-z0-9_$]*` ≤ 63 bytes; user is `all` or such an identifier; address is IPv4/IPv6 CIDR or `all|samehost|samenet`; at most 100 rules.
- Invalid rules → HTTP 422 problem+json, code `invalid_pg_hba` (this repo uses 422 for spec rejections, not 400).
- Never hand-edit `spec/openapi.yaml` or `ui/src/app/api/**`; regenerate with `make openapi ui-client` and commit together with code.
- Rust edition 2024; clippy denies warnings and `unwrap_used`. All UI strings through Transloco (`ui/public/i18n/en.json`).

```rust
//! Client access rules (pg_hba.conf) expressed as structured, validated data.
//!
//! pg_hba is first-match-wins, so placement is the safety model: the managed
//! prefix (local/loopback access, the replication rule) always comes first and
//! the scram catch-all always comes last. User rules sit in between — they can
//! tighten access with explicit `reject` rules but can never break HA, lock
//! out the agent, or silently drop all auth.

use serde::{Deserialize, Serialize};

/// Generous ceiling; real deployments have a handful of rules.
pub const MAX_RULES: usize = 100;

#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize, utoipa::ToSchema)]
#[serde(rename_all = "lowercase")]
pub enum HbaConn {
    Host,
    HostSsl,
    HostNoSsl,
}

impl HbaConn {
    fn as_str(self) -> &'static str {
        match self {
            HbaConn::Host => "host",
            HbaConn::HostSsl => "hostssl",
            HbaConn::HostNoSsl => "hostnossl",
        }
    }
}

/// Deliberately small: cert needs TLS (not built), ldap/radius need auth
/// options this schema does not carry, md5 is deprecated. Growing the list
/// later is backwards-compatible; shrinking it is not.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize, utoipa::ToSchema)]
pub enum HbaMethod {
    #[serde(rename = "scram-sha-256")]
    ScramSha256,
    #[serde(rename = "reject")]
    Reject,
    #[serde(rename = "trust")]
    Trust,
}

impl HbaMethod {
    fn as_str(self) -> &'static str {
        match self {
            HbaMethod::ScramSha256 => "scram-sha-256",
            HbaMethod::Reject => "reject",
            HbaMethod::Trust => "trust",
        }
    }
}

/// One user-supplied pg_hba rule. `local` is not expressible: the managed
/// prefix owns socket access, and a user local rule after `local all all peer`
/// could never match anyway.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize, utoipa::ToSchema)]
pub struct HbaRule {
    pub conn: HbaConn,
    /// "all", "replication", or a single database name.
    pub database: String,
    /// "all" or a single role name.
    pub user: String,
    /// CIDR ("10.0.0.0/8", "::1/128") or all | samehost | samenet.
    pub address: String,
    pub method: HbaMethod,
}

#[derive(Debug, thiserror::Error, PartialEq, Eq)]
pub enum HbaError {
    #[error("too many pg_hba rules: {0} (max {MAX_RULES})")]
    TooManyRules(usize),
    #[error(
        "invalid pg_hba {field} '{value}': must be a keyword or an identifier \
         (letter or _, then letters, digits, _ or $; at most 63 bytes)"
    )]
    BadToken { field: &'static str, value: String },
    #[error(
        "invalid pg_hba address '{0}': must be a CIDR like '10.0.0.0/8' or '::1/128', \
         or one of all, samehost, samenet (hostnames are not supported)"
    )]
    BadAddress(String),
}

pub fn validate_rules(rules: &[HbaRule]) -> Result<(), HbaError> {
    if rules.len() > MAX_RULES {
        return Err(HbaError::TooManyRules(rules.len()));
    }
    for rule in rules {
        check_token("database", &rule.database, &["all", "replication"])?;
        check_token("user", &rule.user, &["all"])?;
        check_address(&rule.address)?;
    }
    Ok(())
}

fn check_token(field: &'static str, value: &str, keywords: &[&str]) -> Result<(), HbaError> {
    if keywords.contains(&value) {
        return Ok(());
    }
    let mut chars = value.chars();
    let head_ok = chars
        .next()
        .is_some_and(|c| c.is_ascii_alphabetic() || c == '_');
    let ok = head_ok
        && value.len() <= 63
        && chars.all(|c| c.is_ascii_alphanumeric() || c == '_' || c == '$');
    if ok {
        Ok(())
    } else {
        Err(HbaError::BadToken {
            field,
            value: value.to_string(),
        })
    }
}

fn check_address(value: &str) -> Result<(), HbaError> {
    if matches!(value, "all" | "samehost" | "samenet") {
        return Ok(());
    }
    let bad = || HbaError::BadAddress(value.to_string());
    let (addr, prefix) = value.split_once('/').ok_or_else(bad)?;
    let ip: std::net::IpAddr = addr.parse().map_err(|_| bad())?;
    let bits: u8 = prefix.parse().map_err(|_| bad())?;
    let max = if ip.is_ipv4() { 32 } else { 128 };
    if bits > max { Err(bad()) } else { Ok(()) }
}

/// The entire pg_hba.conf as a pure function of the spec. The prefix mirrors
/// what initdb produced before this feature (`--auth-local peer --auth-host
/// scram-sha-256`, or `-A trust` without a password), so upgrading rewrites
/// the file without changing its effective rules.
pub fn render(rules: &[HbaRule], repl_user: &str, scram: bool) -> String {
    let mut out =
        String::from("# Managed by pglord - do not edit; changes come from the cluster spec.\n");
    if scram {
        out.push_str("local all all peer\n");
        out.push_str("host all all 127.0.0.1/32 scram-sha-256\n");
        out.push_str("host all all ::1/128 scram-sha-256\n");
        out.push_str("local replication all peer\n");
        out.push_str(&format!(
            "host replication {repl_user} 0.0.0.0/0 scram-sha-256\n"
        ));
    } else {
        out.push_str("# INSECURE trust mode: no password configured.\n");
        out.push_str("local all all trust\n");
        out.push_str("host all all 127.0.0.1/32 trust\n");
        out.push_str("host all all ::1/128 trust\n");
        out.push_str("local replication all trust\n");
        out.push_str("host replication all 0.0.0.0/0 trust\n");
    }
    if !rules.is_empty() {
        out.push_str("\n# User rules (cluster spec pg_hba)\n");
        for r in rules {
            out.push_str(&format!(
                "{} {} {} {} {}\n",
                r.conn.as_str(),
                r.database,
                r.user,
                r.address,
                r.method.as_str()
            ));
        }
    }
    out.push_str("\n# Managed catch-all\n");
    if scram {
        out.push_str("host all all 0.0.0.0/0 scram-sha-256\n");
    } else {
        out.push_str("host all all 0.0.0.0/0 trust\n");
    }
    out
}
```

`write_if_changed` and `write_archive_if_changed` already duplicate the compare-then-write shape; a third copy would make it worse. In `crates/pglord-agent/src/params.rs`, add the shared helper and rewrite all three on top of it:

```rust
/// Write `rendered` to `path` unless it already has exactly that content;
/// returns whether anything was written. Content comparison is what keeps the
/// agent from signalling postgres on every poll.
fn write_file_if_changed(path: &Path, rendered: &str) -> std::io::Result<bool> {
    if let Ok(existing) = std::fs::read_to_string(path)
        && existing == rendered
    {
        return Ok(false);
    }
    std::fs::write(path, rendered)?;
    Ok(true)
}

/// Write the rendered parameters, returning whether the content changed.
pub fn write_if_changed(pgdata: &Path, rendered: &str) -> std::io::Result<bool> {
    write_file_if_changed(&pgdata.join(PARAMS_FILE), rendered)
}

/// Write the archiving file when it differs; returns whether it changed.
pub fn write_archive_if_changed(pgdata: &Path, rendered: &str) -> std::io::Result<bool> {
    write_file_if_changed(&pgdata.join(ARCHIVE_FILE), rendered)
}
```

```markdown
## Client access rules (pg_hba)

Each cluster carries a list of `pg_hba.conf` rules, edited on the cluster page
("Client access rules") or via `PATCH /api/v1/clusters/{name}` with a `pg_hba`
array. A rule has a connection type (`host`, `hostssl`, `hostnossl`), a
database (`all`, `replication`, or one database name), a user (`all` or one
role name), an address (a CIDR like `10.0.0.0/8` or `::1/128`, or `all`,
`samehost`, `samenet`), and an auth method (`scram-sha-256`, `reject`,
`trust`).

PostgreSQL evaluates pg_hba rules first match wins, and pglord fixes the ends
of the file: replication and local socket access always come first (so a rule
cannot break HA or the agent), and a catch-all accepting any
password-authenticated client always comes last. Your rules sit in between —
which means they mostly matter for *tightening*: a `reject` rule matches
before the catch-all and turns clients away. Example: reject one role from
everywhere, then allow everyone else implicitly:

    host  all  contractor  0.0.0.0/0  reject

Changes apply with a configuration reload — connections already established
are not re-checked, and no instance restarts. Rules apply identically on every
instance, primary and standbys. Rule changes are validated up front; a rule
that does not pass (bad CIDR, unknown method, hostname addresses) is rejected
with HTTP 422 and applies nothing.
```
