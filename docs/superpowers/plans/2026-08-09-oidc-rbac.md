# OIDC RBAC-Mapped Authorization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Authorize OIDC credentials through Kubernetes RBAC instead of granting them full admin, add a `whoami` endpoint, and fix the SPA defects on the same paths, per `docs/superpowers/specs/2026-08-09-oidc-rbac-design.md`.

**Architecture:** No new middleware and no new permission model. `OidcValidator::validate` starts returning the claims it already decodes; a pure `SubjectMapping` turns those claims into a Kubernetes `Subject`; the stage-C `KubernetesAuthorizer::authorize` is refactored to take that subject explicitly instead of reading groups from its own TokenReview cache, and is then shared by both paths. New `GET /api/v1/auth/whoami` reads an `Identity` the middleware puts in request extensions.

**Tech Stack:** Rust (axum 0.8, existing `jsonwebtoken`/`kube`/`k8s-openapi`/`sha2`, no new crates), Angular 22 (signals, Transloco), Helm + raw manifests.

## Global Constraints

- Never hand-edit `spec/openapi.yaml` or `ui/src/app/api/**`. Run `make openapi ui-client` and commit the regenerated files with the code that changed the contract.
- Clippy warns on `unwrap_used`; edition 2024; `make lint` must pass.
- All user-visible UI strings go through Transloco (`ui/public/i18n/en.json`).
- No new problem codes. Reuse `auth_invalid` (401) and `forbidden` (403) exactly as stage C defined them.
- `PGLORD_AUTH_OIDC_RBAC` defaults to false: an install that does not set it behaves byte-identically to today. This is the back-compat contract for every task.
- A missing Kubernetes environment must produce 401, never 500 — the stage-C constraint, now on the OIDC path too.
- `Config::test_default()` gains every new field so existing tests keep compiling.
- `deploy/k8s/` and `charts/pglord/` change together.

## Self-review notes

- **Spec coverage:** mode/configuration → T1; claims→subject → T2; one-authorizer refactor → T3; middleware branch + Identity → T4; whoami + scopes contract → T5; SPA correctness fixes → T6; testing (UI half) → T7; deployment + docs → T8. The spec's Errors table is asserted across T1 (startup failure), T4 (401 rows), and T5.
- **Type consistency:** `Subject` and `SubjectMapping` are defined in T2 and consumed in T3, T4, T5. `Identity` is defined in T4 and consumed only in T5. `validate`'s return type changes in T2, which is the first task that touches every existing `jwks.rs` test — do not split that change across tasks or the tree will not compile between commits.
- **Ordering constraint:** T3 must land before T4. T4 changes `AuthState`'s shape, which T5's handler depends on through the extension, so T5 cannot be pulled forward.
- **Known naming decision to hold:** `AuthState.kubernetes` becomes two fields (`k8s_tokens`, `reviews`) in T4. Grep for the old field before starting T4 — `app.rs` constructs `AuthState` and `preflight` reads the config flags, not the state, so the blast radius should be `auth/mod.rs` alone.
- **Back-compat check to run at the end of T4:** with `PGLORD_AUTH_OIDC_RBAC` unset, the middleware must take exactly the branch it takes today. The `oidc_rbac_off_keeps_full_admin` test is the guard; it is deliberately asserting current behavior rather than desired behavior, and it should be deleted the day the default flips.
