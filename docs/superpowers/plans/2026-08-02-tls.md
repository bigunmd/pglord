# TLS for Postgres Connections Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Encrypt client/replication traffic with a user-referenced `kubernetes.io/tls` Secret and support client-cert auth via a pg_hba `cert` method.

**Architecture:** New `TlsSpec` block on `ClusterSpec`; `render.rs` mounts the Secret read-only at `/etc/pglord/tls` (`defaultMode 0o640`, works with the existing `fsGroup: 999`); the agent renders a fifth managed conf include `postgresql.pglord-tls.conf` on its 5s converge pass and detects cert rotation by hashing the mounted files. Spec: `docs/superpowers/specs/2026-08-02-tls-design.md`.

**Tech Stack:** Rust (axum/utoipa/kube-rs), Angular + generated TS client, bash e2e on the minikube stand.

## Global Constraints

- Never hand-edit `spec/openapi.yaml` or `ui/src/app/api/**` — regenerate with `make openapi ui-client` after DTO changes and commit together.
- `make lint` must pass: `cargo fmt --all --check` + clippy `-D warnings` (clippy warns on `unwrap_used`; tests use `expect`).
- Rust edition 2024. Run targeted tests with `cargo test -p <crate> <name>`.
- The agent must never write `ssl = on` unless the cert files are actually present on disk — a crash-restart with `ssl = on` and no cert would prevent Postgres from starting (design §Agent).
- UI strings go through Transloco (`ui/public/i18n/`); API access only through the generated client.

```rust
//! TLS for client and replication connections.
//!
//! pglord never generates key material: the spec references a standard
//! `kubernetes.io/tls` Secret (tls.crt/tls.key, optional ca.crt) that
//! something else — typically cert-manager — creates and renews. The
//! reconciler mounts it; the agent turns it into a managed conf include.

use serde::{Deserialize, Serialize};

/// Where the reconciler mounts the server certificate Secret.
pub const TLS_MOUNT: &str = "/etc/pglord/tls";
pub const TLS_VOLUME: &str = "tls-certs";
/// Keys of a standard kubernetes.io/tls Secret.
pub const TLS_CERT_KEY: &str = "tls.crt";
pub const TLS_KEY_KEY: &str = "tls.key";
/// Optional CA bundle key (cert-manager writes it); required for `cert` auth.
pub const TLS_CA_KEY: &str = "ca.crt";

#[derive(Debug, Clone, Default, PartialEq, Eq, Serialize, Deserialize, utoipa::ToSchema)]
pub struct TlsSpec {
    /// kubernetes.io/tls Secret with the server certificate. TLS is enabled
    /// iff this is set.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub server_secret: Option<String>,
}

impl TlsSpec {
    /// The Secret name, ignoring blanks a form might send.
    pub fn server_secret(&self) -> Option<&str> {
        self.server_secret.as_deref().map(str::trim).filter(|s| !s.is_empty())
    }
    pub fn enabled(&self) -> bool {
        self.server_secret().is_some()
    }
}

#[derive(Debug, thiserror::Error, PartialEq, Eq)]
pub enum TlsError {
    #[error("invalid TLS secret name '{0}': must be a lowercase RFC1123 name")]
    InvalidSecretName(String),
}

pub fn validate(t: &TlsSpec) -> Result<(), TlsError> { /* rfc1123 subdomain check like init.rs */ }

/// The managed conf include. `enabled` must already account for the cert
/// files being present on disk (agent-side guard): postgres refuses to START
/// with `ssl = on` and no certificate, so a pre-roll pod must keep ssl off.
pub fn conf(enabled: bool, ca_present: bool) -> String {
    let mut out = String::from("# Managed by pglord — do not edit; changes come from the cluster spec.\n");
    if enabled {
        out.push_str("ssl = on\n");
        out.push_str(&format!("ssl_cert_file = '{TLS_MOUNT}/{TLS_CERT_KEY}'\n"));
        out.push_str(&format!("ssl_key_file = '{TLS_MOUNT}/{TLS_KEY_KEY}'\n"));
        if ca_present {
            out.push_str(&format!("ssl_ca_file = '{TLS_MOUNT}/{TLS_CA_KEY}'\n"));
        }
    } else {
        out.push_str("ssl = off\n");
    }
    out
}
```

Tests: blank name counts as disabled; bad names rejected; `conf(true, false)` has cert/key but no ca line; `conf(true, true)` has ca; `conf(false, _)` renders explicit `ssl = off` (mirrors sync.rs "explicit empty value" rationale — disabling must clear on reload).

- [ ] **Step 2: Implement** — `TLS_FILE` const + three-line `write_tls_if_changed`. Rotation marker reuses `write_file_if_changed` for idempotence: hash the mounted files and store the digest in `PGDATA/postgresql.pglord-tls.hash`; a differing digest means kubelet swapped the certs, and the returned `true` rides the existing single-reload path (postgres re-reads certs on SIGHUP). Hash with `std::hash::DefaultHasher` — change detection, not security; a spurious reload after an agent upgrade is harmless:

```rust
/// Digest of the mounted cert files, stored so a cert-manager renewal
/// (kubelet swapping the projected files) triggers exactly one reload.
pub fn write_tls_rotation_marker(pgdata: &Path, cert_dir: &Path) -> std::io::Result<bool> {
    use std::hash::{DefaultHasher, Hash, Hasher};
    let mut h = DefaultHasher::new();
    for key in [pglord_core::tls::TLS_CERT_KEY, pglord_core::tls::TLS_KEY_KEY, pglord_core::tls::TLS_CA_KEY] {
        match std::fs::read(cert_dir.join(key)) {
            Ok(bytes) => { key.hash(&mut h); bytes.hash(&mut h); }
            Err(_) => "absent".hash(&mut h),
        }
    }
    write_file_if_changed(&pgdata.join("postgresql.pglord-tls.hash"), &format!("{:x}\n", h.finish()))
}
```
