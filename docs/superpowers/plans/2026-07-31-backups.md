# Backups (pgBackRest) — Slice 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Back a cluster up to S3-compatible object storage and see the backups that exist. Taking and listing backups only — scheduling and restore are the following slices, called out explicitly so nobody mistakes this for a complete backup story.

**Architecture:** pgBackRest runs inside the instance pods (installed in the agent image), configured from the cluster spec by the agent — the same path that already applies PostgreSQL parameters. The primary owns the stanza and takes backups; the agent exposes `POST /backup` and `GET /backups` on its control endpoint, and the server fans those out to the recorded primary. Object-storage credentials come from a user-provided Secret referenced by name, never from the spec itself.

**Tech Stack:** pgBackRest (MIT, AGPL-compatible) in the agent image; MinIO on the dev stand for the e2e.

## Global Constraints

- Credentials live in a Secret the user creates (`s3_credentials_secret` with keys `access-key` / `secret-key`); the spec holds only its name. Never log or echo them.
- WAL archiving is enabled **only** when backups are configured; otherwise `archive_mode` stays off so a cluster without a repository cannot fill its disk with unarchivable WAL.
- `archive_command`/`archive_mode` join the reserved GUC list — they are managed, not tunable.
- Enabling backups requires a restart (`archive_mode` is restart-only); surface that through the existing `pending_restart` path rather than restarting behind the user's back.
- Backups run on the **recorded primary** only.
- Restore and scheduling are out of scope; the UI and docs must say so plainly.

## Tasks

### B1: Backup spec + reserved GUCs (core)
`crates/pglord-core/src/backup.rs`: `BackupSpec { enabled: bool, s3_endpoint, s3_bucket, s3_region, s3_credentials_secret: Option<String>, retention_full: u8 (default 2), path_prefix: Option<String> }`, `validate()` (when enabled: endpoint/bucket/secret required, endpoint must be a URL, retention 1–52), `pgbackrest_conf(cluster, spec) -> String` renderer, and `archive_command()`.
`ClusterSpec` gains `backup: BackupSpec`; `SpecChange` gains `backup: Option<BackupSpec>`. Add `archive_mode`, `archive_command`, `archive_timeout` to `guc::RESERVED`.
Tests: disabled spec always valid; enabled without bucket/secret rejected; conf renders repo1-s3 keys and retention; reserved GUCs rejected via the existing parameter path.

### B2: Agent takes and lists backups
- `deploy/Dockerfile.agent`: install `pgbackrest` from the pgdg repo already present in `postgres:17`.
- `crates/pglord-agent/src/backup.rs`: write `/etc/pgbackrest/pgbackrest.conf` from the spec (same follow loop as parameters, credentials read from mounted env), `stanza_create()` (idempotent, primary only), `take_backup(kind)` → `pgbackrest --stanza=<cluster> backup --type=full|incr`, `list_backups()` → parse `pgbackrest info --output=json` into `Vec<BackupInfo { label, kind, started, finished, size_bytes, wal_start, wal_end }>`.
- Managed `postgresql.conf` gains `archive_mode = on` + `archive_command` **only when backups are enabled**.
- Agent HTTP: `POST /backup` (409 when not primary or backups disabled), `GET /backups`.
- Tests: conf rendering; `info --output=json` parsing from a captured fixture; archive settings absent when disabled.

### B3: Server API
- `POST /clusters/{name}/backups` → 202, proxied to the recorded primary's agent (409 `backups_disabled`, 409 `no_primary`).
- `GET /clusters/{name}/backups` → `{ backups: [...] , repository: "s3://bucket/prefix" }`; empty list when disabled.
- `PATCH /clusters/{name}` accepts `backup`; `ClusterDetail` gains `backup` (secret name only, never values).
- Regenerate spec + TS client in the same commit.

### B4: UI
Backups section on the cluster detail page: repository summary, **Back up now**, table of backups (label, type, size, finished), empty state explaining backups are off with a link to the editor, and a dialog to configure the repository (endpoint, bucket, region, secret name, retention). A clear note that restore and scheduling are not available yet.

### B5: e2e + docs
`scripts/backup-e2e.sh` + `make backup-e2e`: deploy MinIO on the stand (`deploy/k8s/dev/minio.yaml`, dev-only), create bucket, create the credentials Secret, create a cluster with backups enabled, restart to pick up `archive_mode`, `POST /backups`, poll `GET /backups` until one full backup is listed, assert WAL archived to the bucket, delete.
`docs/user-guide.md`: "Backups" section — configuring a repository, taking a backup, what is *not* yet covered (no schedule, no restore), and that a `pg_dump` remains the fallback until restore ships.
