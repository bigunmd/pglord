# Credentials Rotation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `POST /api/v1/clusters/{name}/rotate-credentials` rotates both managed passwords end to end: Secret patch → `ALTER ROLE` on the primary via a new agent endpoint → rolling restart, with a UI confirm dialog.

**Architecture:** The agent gains `POST /roles/apply` (primary-only, reusing postboot's dollar-quoted DDL, extracted into shared helpers) and an idempotent `primary_conninfo` refresh on every standby boot (closes the persisted-old-password hazard). The server gains a detached four-step rotation task (generate → patch Secret → agent ALTER → roll pods) with the pod-roll loop extracted from `restart_cluster` for reuse.

**Tech Stack:** Rust (axum 0.8, kube-rs, tokio-postgres), Angular + generated ng-openapi-gen client, Transloco i18n.

Spec: `docs/superpowers/specs/2026-08-01-credentials-rotation-design.md`.

## Global Constraints

- Managed Secrets only: a cluster with `spec.credentials_secret` set gets 409 `custom_credentials_secret`. pglord never writes a Secret it does not own.
- Passwords are always server-generated by the existing `reconciler::generate_password()` (32-char alphanumeric); the agent re-validates with `postboot::is_safe_password` before interpolating into DDL, and validates charset BEFORE querying postgres so the 400 path needs no database.
- API contract changes: after the server route lands, run `make openapi ui-client` and commit `spec/openapi.yaml` + `ui/src/app/api/**` together with the code. Never hand-edit either.
- Roll order is always standbys first, primary last.
- Clippy warns on `unwrap_used`; use `expect("...")`/`unwrap_or_default()` as the codebase does.

```rust
/// Local superuser connection over the socket (peer auth — works even when
/// the env password is stale, which is the whole point during rotation).
async fn connect_local(
    cfg: &Config,
) -> anyhow::Result<(
    tokio_postgres::Client,
    tokio::task::JoinHandle<Result<(), tokio_postgres::Error>>,
)> {
    let conn_str = format!(
        "host={} port={} user={} password={} dbname=postgres connect_timeout=5",
        cfg.socket_dir.display(),
        cfg.port,
        cfg.superuser,
        cfg.superuser_password,
    );
    let (client, connection) = tokio_postgres::connect(&conn_str, tokio_postgres::NoTls).await?;
    Ok((client, tokio::spawn(connection)))
}

/// CREATE or ALTER the replication role with the given password.
async fn ensure_repl_role(
    client: &tokio_postgres::Client,
    repl_user: &str,
    repl_password: &str,
) -> anyhow::Result<()> {
    if repl_user.is_empty() || !repl_user.chars().all(|c| c.is_ascii_alphanumeric() || c == '_') {
        anyhow::bail!("repl_user must be non-empty alphanumeric/underscore");
    }
    if !is_safe_password(repl_password) {
        anyhow::bail!("repl_password may only contain [A-Za-z0-9_-]");
    }
    let exists: bool = client
        .query_one(
            "SELECT EXISTS(SELECT 1 FROM pg_roles WHERE rolname = $1)",
            &[&repl_user],
        )
        .await?
        .get(0);
    let verb = if exists { "ALTER" } else { "CREATE" };
    client
        .batch_execute(&format!(
            "{verb} ROLE \"{repl_user}\" WITH REPLICATION LOGIN PASSWORD $pglord${repl_password}$pglord$"
        ))
        .await?;
    Ok(())
}

/// ALTER the superuser's password.
async fn alter_superuser(
    client: &tokio_postgres::Client,
    superuser: &str,
    superuser_password: &str,
) -> anyhow::Result<()> {
    if !is_safe_password(superuser_password) {
        anyhow::bail!("superuser_password may only contain [A-Za-z0-9_-]");
    }
    if !superuser.chars().all(|c| c.is_ascii_alphanumeric() || c == '_') {
        anyhow::bail!("superuser must be alphanumeric/underscore");
    }
    client
        .batch_execute(&format!(
            "ALTER ROLE \"{superuser}\" WITH PASSWORD $pglord${superuser_password}$pglord$"
        ))
        .await?;
    Ok(())
}

/// Apply NEW passwords to both roles in one connection. Used by the rotation
/// endpoint; postboot's own startup path keeps applying the env passwords.
pub async fn apply_passwords(
    cfg: &Config,
    superuser_password: &str,
    repl_password: &str,
) -> anyhow::Result<()> {
    let (client, conn_task) = connect_local(cfg).await?;
    ensure_repl_role(&client, &cfg.repl_user, repl_password).await?;
    alter_superuser(&client, &cfg.superuser, superuser_password).await?;
    drop(client);
    conn_task.abort();
    Ok(())
}
```

```rust
#[derive(serde::Deserialize)]
struct RolesRequest {
    superuser_password: String,
    repl_password: String,
}

/// Apply new role passwords. Primary only: standbys' pg_authid is replicated.
/// Charset is validated before any postgres access so a bad request is 400
/// even when postgres is down.
async fn apply_roles(
    State(cfg): State<Arc<Config>>,
    Json(req): Json<RolesRequest>,
) -> impl IntoResponse {
    if !crate::postboot::is_safe_password(&req.superuser_password)
        || !crate::postboot::is_safe_password(&req.repl_password)
    {
        return (
            StatusCode::BAD_REQUEST,
            Json(serde_json::json!({ "error": "passwords may only contain [A-Za-z0-9_-]" })),
        );
    }
    let st = status::query_status(&cfg).await;
    if st.in_recovery != Some(false) {
        return (
            StatusCode::CONFLICT,
            Json(serde_json::json!({ "error": "role changes run on the primary only" })),
        );
    }
    match crate::postboot::apply_passwords(&cfg, &req.superuser_password, &req.repl_password).await
    {
        Ok(()) => (
            StatusCode::OK,
            Json(serde_json::json!({ "status": "applied" })),
        ),
        Err(err) => (
            StatusCode::INTERNAL_SERVER_ERROR,
            Json(serde_json::json!({ "error": err.to_string() })),
        ),
    }
}
```

```rust
/// Replace every primary_conninfo line in postgresql.auto.conf with `line`.
/// The password inside primary_conninfo is persisted at bootstrap; without
/// this refresh a standby restarted after a credentials rotation would keep
/// streaming with the old password forever.
pub fn refresh_conninfo(pgdata: &Path, line: &str) -> anyhow::Result<()> {
    let path = pgdata.join("postgresql.auto.conf");
    let existing = std::fs::read_to_string(&path).unwrap_or_default();
    let mut kept: String = existing
        .lines()
        .filter(|l| !l.trim_start().starts_with("primary_conninfo"))
        .map(|l| format!("{l}\n"))
        .collect();
    kept.push_str(line);
    std::fs::write(&path, kept).context("write postgresql.auto.conf")?;
    Ok(())
}
```

```rust
/// Standbys first, primary last: writes stay available for as long as possible.
pub(crate) fn roll_order(cluster: &str, replicas: u8, primary: &str) -> Vec<String> {
    let mut order: Vec<String> = (0..replicas)
        .map(|i| format!("{cluster}-{i}"))
        .filter(|p| p != primary)
        .collect();
    order.push(primary.to_string());
    order
}

/// Delete each pod in order, waiting for it to come back ready before the
/// next, so the cluster never loses more than one instance at a time.
pub(crate) async fn roll_pods(
    ops: &ClusterOps,
    spec: &pglord_core::spec::ClusterSpec,
    order: Vec<String>,
) {
    let pods: Api<k8s_openapi::api::core::v1::Pod> = Api::namespaced(ops.kube.clone(), &ops.ns);
    for pod in order {
        if let Err(err) = pods.delete(&pod, &Default::default()).await {
            tracing::warn!(%pod, %err, "roll: pod delete failed");
            continue;
        }
        for _ in 0..60u32 {
            tokio::time::sleep(std::time::Duration::from_secs(2)).await;
            let obs = crate::instance_probe::observe_cluster(
                &ops.http,
                &spec.name,
                &ops.ns,
                spec.replicas,
            )
            .await;
            if obs.iter().any(|o| o.pod == pod && o.ready) {
                break;
            }
        }
        tracing::info!(%pod, "roll: instance back");
    }
}
```

```rust
/// Rotate the managed credentials: new generated passwords are written to the
/// Secret, applied on the primary, then every instance is restarted.
#[utoipa::path(
    post,
    path = "/api/v1/clusters/{name}/rotate-credentials",
    tag = "clusters",
    params(("name" = String, Path, description = "Cluster name")),
    responses(
        (status = 202, description = "Rotation started"),
        (status = 404, description = "Not found", body = crate::error::ProblemDetails, content_type = "application/problem+json"),
        (status = 409, description = "Cluster uses a user-supplied credentials Secret", body = crate::error::ProblemDetails, content_type = "application/problem+json"),
    )
)]
pub async fn rotate_credentials(
    State(state): State<Option<ClusterOps>>,
    Path(name): Path<String>,
) -> Result<StatusCode, ApiError> {
    let ops = ops(&state)?;
    let Some((spec, _owner)) = ops.store.get(&name).await.map_err(ApiError::internal)? else {
        return Err(ApiError::not_found());
    };
    if spec.credentials_secret().is_some() {
        return Err(ApiError::conflict("custom_credentials_secret").with_detail(
            "This cluster reads credentials from your own Secret; pglord only rotates the Secret it manages.",
        ));
    }
    let primary = ops
        .store
        .primary(&name)
        .await
        .map_err(ApiError::internal)?
        .unwrap_or_else(|| format!("{name}-0"));

    let ops = ops.clone();
    tokio::spawn(async move {
        let outcome = match run_rotation(&ops, &spec, &primary).await {
            Ok(()) => {
                tracing::info!(cluster = %spec.name, "credentials rotation finished");
                "succeeded"
            }
            Err(err) => {
                tracing::error!(cluster = %spec.name, %err, "credentials rotation failed; re-POST to converge");
                "failed"
            }
        };
        ops.metrics
            .rotations_total
            .with_label_values(&[spec.name.as_str(), outcome])
            .inc();
    });
    Ok(StatusCode::ACCEPTED)
}

/// The four idempotent steps. Any failure leaves a state a re-run converges:
/// the Secret write and the ALTERs are both last-writer-wins, and the roll is
/// a plain restart.
async fn run_rotation(
    ops: &ClusterOps,
    spec: &pglord_core::spec::ClusterSpec,
    primary: &str,
) -> anyhow::Result<()> {
    let su_pw = crate::reconciler::generate_password();
    let repl_pw = crate::reconciler::generate_password();

    let secrets: Api<Secret> = Api::namespaced(ops.kube.clone(), &ops.ns);
    let patch = serde_json::json!({
        "metadata": { "annotations": {
            "pglord.dev/rotated-at": chrono::Utc::now().to_rfc3339(),
        } },
        "stringData": {
            SUPERUSER_PASSWORD_KEY: su_pw,
            REPLICATION_PASSWORD_KEY: repl_pw,
        },
    });
    secrets
        .patch(
            &credentials_secret_name(&spec.name),
            &PatchParams::default(),
            &Patch::Merge(&patch),
        )
        .await?;
    tracing::info!(cluster = %spec.name, "rotation: secret updated");

    let url = format!(
        "http://{}:{}/roles/apply",
        pod_fqdn(primary, &spec.name, &ops.ns),
        AGENT_HTTP_PORT
    );
    let resp = ops
        .http
        .post(&url)
        .json(&serde_json::json!({
            "superuser_password": su_pw,
            "repl_password": repl_pw,
        }))
        .send()
        .await?;
    if !resp.status().is_success() {
        let status = resp.status();
        let body = resp.text().await.unwrap_or_default();
        anyhow::bail!("agent /roles/apply on {primary} answered {status}: {body}");
    }
    tracing::info!(cluster = %spec.name, %primary, "rotation: roles altered on primary");

    let order = crate::api::clusters::roll_order(&spec.name, spec.replicas, primary);
    crate::api::clusters::roll_pods(ops, spec, order).await;
    Ok(())
}
```

Note: `su_pw`/`repl_pw` are moved into the patch json before the agent call — `serde_json::json!` takes them by value. Build the agent body from clones (`"superuser_password": su_pw.clone()` in the patch, or clone where needed) so both uses compile; prefer cloning in the *patch* and moving into the *agent body*.

```bash
echo "==> rotation refuses a cluster with a user-supplied secret"
code=$(curl -s -o /dev/null -w '%{http_code}' -X POST "$API/api/v1/clusters/sec/rotate-credentials")
[ "$code" = "409" ] || { echo "FAIL: rotate on custom-secret cluster -> $code, expected 409"; exit 1; }
echo "OK custom-secret cluster refused"

echo "==> rotating a managed cluster"
curl -s -X POST "$API/api/v1/clusters" -H 'content-type: application/json' \
  -d "{\"name\":\"rot\",\"replicas\":2,\"image\":\"$AGENT_IMAGE\"}" >/dev/null
for _ in $(seq 1 90); do
  [ "$(field rot '' "['ready_replicas']")" = "2" ] && break
  sleep 2
done
[ "$(field rot '' "['ready_replicas']")" = "2" ] || { echo "FAIL: rot never became ready"; exit 1; }
old_pw=$($KUBECTL -n pglord get secret rot-credentials -o jsonpath='{.data.superuser-password}' | base64 -d)
curl -s -o /dev/null -X POST "$API/api/v1/clusters/rot/rotate-credentials"
# Rotation rolls both pods; wait for the secret to change, then for readiness.
for _ in $(seq 1 90); do
  new_pw=$($KUBECTL -n pglord get secret rot-credentials -o jsonpath='{.data.superuser-password}' | base64 -d)
  [ "$new_pw" != "$old_pw" ] && break
  sleep 2
done
[ "$new_pw" != "$old_pw" ] || { echo "FAIL: secret password never changed"; exit 1; }
rotated_at=$($KUBECTL -n pglord get secret rot-credentials -o jsonpath='{.metadata.annotations.pglord\.dev/rotated-at}')
[ -n "$rotated_at" ] || { echo "FAIL: rotated-at annotation missing"; exit 1; }
for _ in $(seq 1 120); do
  [ "$(field rot '' "['ready_replicas']")" = "2" ] && break
  sleep 2
done
[ "$(field rot '' "['ready_replicas']")" = "2" ] || { echo "FAIL: rot not ready after rotation"; exit 1; }
# TCP auth uses scram: the new password must work, the old must not.
ok=$($KUBECTL -n pglord exec rot-0 -- env PGPASSWORD="$new_pw" psql -h rot-rw -U postgres -tAc "SELECT 1" 2>/dev/null || echo "")
[ "$ok" = "1" ] || { echo "FAIL: new password rejected"; exit 1; }
bad=$($KUBECTL -n pglord exec rot-0 -- env PGPASSWORD="$old_pw" psql -h rot-rw -U postgres -tAc "SELECT 1" 2>/dev/null || echo "")
[ "$bad" != "1" ] || { echo "FAIL: old password still accepted"; exit 1; }
# The standby must still be streaming after the roll (conninfo refreshed).
streaming=$(psql_on rot-0 "SELECT count(*) FROM pg_stat_replication")
[ "$streaming" = "1" ] || { echo "FAIL: standby not streaming after rotation (got '$streaming')"; exit 1; }
echo "OK rotation: new password works, old rejected, standby streaming"
curl -s -X DELETE "$API/api/v1/clusters/rot" >/dev/null
```

```markdown
### Rotating credentials

For clusters whose credentials pglord generated (no user-supplied Secret),
**Rotate passwords** on the cluster page — or
`POST /api/v1/clusters/<name>/rotate-credentials` — replaces both the
superuser and replication passwords in one operation: new values are written
to the `<name>-credentials` Secret, applied on the primary, and every
instance is restarted one at a time, standbys first. The Secret's
`pglord.dev/rotated-at` annotation records when this last happened.

Connected clients keep working until they reconnect; after that they must
present the new password from the Secret, so update anything that caches it.
Clusters that reference your own Secret are refused (`409
custom_credentials_secret`): pglord does not write to Secrets it does not
own.

The new passwords travel from the server to the primary's agent over
unauthenticated in-cluster HTTP — the same channel the failover promote call
uses. If that is not acceptable in your environment, treat rotation (and
pglord's control plane generally) as trusted-namespace-only.

If a rotation fails partway (the run counter
`pglord_credential_rotations_total{outcome="failed"}` ticks and the log says
so), simply POST it again: every step is idempotent and a re-run converges
the cluster.
```
